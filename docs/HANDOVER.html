What the Finder is — and is not

A Cameroon-first, bilingual (EN/FR) discovery, identity and coordination product: patients find care, facilities stay findable and run their day-to-day interactions with Health ID holders. It is not a hospital information system or an EMR. The yardstick every change was held to is docs/DASHBOARD_SCOPE.md — findable, reachable, counter service with consent, the team, aggregate numbers, money at the counter only. Clinical documentation, admissions/discharge, procurement, HR and insurance are out.

  • Stack: Laravel 13, PHP 8.3, PostgreSQL. Production runs with APP_ENV=demo (public demo logins are on).
  • Sister code: mobile app at C:\laragon\www\opescare-finder-mobile (Expo). The main platform at C:\laragon\www\opescare is read-only — code was imported from it, never edited in it.
  • Non-negotiables: facility id only from the session/auth context, cross-facility = 404, no patient name search, clinical rows are never deleted, care is never gated on payment or the queue, EN/FR strings 1:1.

How to ship safely

There is no CI deploy and no git remote. The recipe that has been used for every release:

  1. Test on your own database. Another local project uses the default test DB. Stream results so a crash cannot hide: 
    DB_DATABASE=opescare_test_t4 /c/laragon/bin/php/php-8.3.30-Win32-vs16-x64/php.exe -d memory_limit=2G vendor/bin/phpunit --teamcity > suite.log 2>&1
    The full suite takes 15–35 minutes. The one “risky” test with no assertions is expected.
  2. Checks: php scripts/i18n-audit.php and php artisan view:cache.
  3. Commit by explicit path and confirm the staged list before committing.
  4. Ship changed files only: git archive the diff, scp it, compare md5, extract in /home/finder/htdocs/finder.opescare.cloud, chown -R finder:finder, then migrate --force and config:cache / route:cache / view:cache. Never ship .env or storage/; remove deleted files on the server by hand.
  5. Restart the queue worker after job changes: systemctl restart finder-queue.service.
  6. Verify live as a demo account. Login is throttled to 5 per minute; platform-admin pages need MFA and cannot be walked with curl.

Traps that cost time here: a stale config:cache can point tests at the dev database; six or more concurrent test runs crash Postgres, and an unclean stop triggers a 30-minute recovery; Windows PHP cannot see Git Bash’s /tmp; IsDemoRecord hides real rows on the demo host.
